# Security Policy

## Supported Versions

Only the latest patch releases of the active major version receive security updates.

| Version | Supported          |
| ------- | ------------------ |
| 1.0.x   | :white_check_mark: |
| < 1.0.0 | :x:                |

## Reporting a Vulnerability

We take the security of SnipCLI seriously. If you discover or suspect a security vulnerability in this project, please report it privately rather than opening a public issue.

### How to Report

1. **GitHub Security Advisory (Primary):**  
   Navigate to the repository's [Security Advisories](https://github.com/chowdhuryrifat/SnipCLI/security/advisories) tab and click **"Report a vulnerability"** to submit private details directly to the maintainers.
2. **Fallback Contact:**  
   If private vulnerability reporting is unavailable, reach out to `67093774+chowdhuryrifat@users.noreply.github.com` with the subject `[SECURITY VULNERABILITY] SnipCLI`.

### What to Include in Your Report

To help us triage and resolve the issue quickly, please provide:
- A description of the vulnerability and its potential impact.
- Step-by-step reproduction instructions, proof-of-concept input, or minimal test cases.
- Operating system, compiler/architecture, and SnipCLI version (`snip --version`).
- Any proposed remediation or patches if available.

## Response Timeline and SLA

- **Acknowledgment & Triage:** Within **48 hours** of initial receipt.
- **Assessment & Status Update:** Within **5 business days** with an evaluation of severity and remediation plan.
- **Fix Target & Disclosure:** Target release of a security patch within **14 calendar days** of confirmation, followed by coordinated public disclosure.
